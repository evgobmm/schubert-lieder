# Подсветка слов под запись и переход по клику

Обновлено: 2026-09-09. Источник — указания пользователя (чат).

## Что делает сайт

- При проигрывании записи в панели «Исполнения» в тексте **подсвечивается пропеваемое слово**:
  в немецкой строке (слева) и соответствующий ему сегмент подстрочника (справа).
  Тянущееся слово подсвечено, пока звучит.
- **Клик по слову в любой колонке** (пока в плеере загружена запись с таймингами) — запись
  перематывается на это слово и играет дальше: по немецкому слову — на него самого, по русскому
  сегменту подстрочника — на первое из его немецких слов. Русское слово без немецкого соответствия
  (добавленное переводом, например «не») ведёт к ближайшему слову той же строки. Если строка спета
  несколько раз, берётся проход, ближайший по времени к текущей позиции записи. Клик по знаку сноски
  по-прежнему открывает пояснение, а не перематывает.
- Пауза записи — подсветка остаётся на месте; конец записи, смена записи, закрытие панели — снимается.
- Прокрутка вслед за подсветкой (компьютер) — только пока читатель за ней следит: если предыдущая
  подсвеченная строка была на экране, а новая ушла за край, страница подтягивает новую строку. Если
  читатель ушёл в другое место страницы (подсвеченной строки на экране нет), подсветка страницу не дёргает.
- **Мобильная раскладка — ведение по тексту**: как только исполнение пошло (плей, в том числе после
  паузы), страница переходит к пропеваемой строке (пока слова ещё нет — к началу текста) и дальше ведёт
  по тексту, подтягивая каждую новую строку в центр экрана. Любое движение пальцем по странице
  (читатель начал читать своё) ведение выключает; касание слова в тексте (перемотка) включает снова.
  Конец записи или её смена — ведение выключено.
- Записи с подсветкой отмечены в списке исполнений значком (подсказка значка: «В этой записи есть
  подсветка слов»). Под плеером у такой записи — текст «Если нажать на слово в тексте, исполнение
  перейдёт на соответствующее место.» и ниже галочка **«Подсвечивать слова по ходу исполнения»**
  (по умолчанию включена; выбор запоминается в браузере). Фразы «Слова подсвечиваются по ходу записи»
  нет. Снятая галочка убирает подсветку и прокрутку вслед за ней; переход по клику на слово работает.
  У записи без подсветки — подсказка, в какой записи песни подсветка есть.

## Где включено

Подсветка работает там, где для выбранной записи есть файл таймингов в `app/src/data/timings/`.
**Пока это только страница «Гретхен за прялкой» (D 118)** — запись Сэмпсон — Миддлтон (2018).
Остальные записи и песни — плеер как раньше, без подсветки. Расширение на другие песни и записи —
отдельное решение пользователя; производство таймингов — `audio-alignment.md`.

## Формат файла таймингов

`app/src/data/timings/d<D>-<videoId>.json` (для D с дробью — `d795-1-<videoId>.json`). Ключ — пара
(D, videoId): тайминги действительны только для той записи, по которой считались.

```json
{
  "d": "118", "videoId": "1F4CHXbX8gc", "performance": "Sampson — Middleton, 2018",
  "method": "…", "verified_by_ear": false,
  "extra_lines": [{ "id": "x1", "de": "…", "note": "…" }],
  "route": [ { "s": 0, "l": 0, "w": [[4.1, 4.52], [4.9, 6.06], …] }, …, { "x": "x1", "w": […] } ]
}
```

- `route` — проходы в порядке звучания; `s`, `l` — строфа и строка `stanzas[s].lines_de[l]`;
  `w[k]` — `[начало, конец]` в секундах k-го слова строки **по пробелам** (интервалов ровно столько,
  сколько слов в строке). Одна строка может встречаться в маршруте сколько угодно раз.
- В проходе `w[k]` может быть `null` — слово в этом проходе не спето (частичный повтор нескольких слов: композитор повторяет «die Erde, die Erde», в тексте повтора нет, подсвечиваются те же слова ещё раз). Индекс слов такие интервалы пропускает.
- `x` — ссылка на строку из `extra_lines` (слова, которых в тексте нет); такой проход ничего
  не подсвечивает.
- Маршрут ссылается на текст **в том виде, в каком он опубликован**. Пока повторы Шуберта в D 118
  вписаны в текст, проходы финальной строфы и коды ссылаются на строфы 10–11; при чистке текста
  (`audio-alignment.md`) маршрут переписывается (в файле есть `note`, что именно).
- `variants` — слова, спетые в этой записи иначе, чем в тексте: `[{s, l, k, w, heard, start}]` (`w` — слово текста,
  `heard` — как спето, по Whisper с подтверждением обоих CTC-движков). **Пока в плеере выбрана такая запись, в немецкой
  строке на месте слова текста показывается спетое** (пунктирное подчёркивание, подсказка «в тексте: …»); текст песни
  не меняется. Пример: Quasthoff в D 911/4 поёт «erfroren» вместо «erstorben».
- `verified_by_ear` — прошла ли разметка приёмку на слух; у D 118 пока `false`: приёмка — на сайте.

## Поведение подсветки (детали реализации)

- Слово подсвечено от `start` до `end`; пауза до 1,0 с до следующего слова закрывается предыдущим
  словом (внутри фразы подсветка не мигает); более долгая (вздох, интерлюдия) — без подсветки.
- Клик перематывает на `start − 0,15 с`, чтобы была слышна атака слова.
- Плеер — YouTube IFrame Player API поверх `youtube-nocookie.com`; позиция опрашивается покадрово
  с интерполяцией между сообщениями плеера. Если API не загрузился (блокировщик, нет сети) —
  обычный iframe, без подсветки.
- Код: `app/src/utils/playback.js` (общее состояние плеера и страницы), `utils/timings.js` (индекс
  слов по времени), `utils/lineTokens.js` (слова строки; слово → сегмент подстрочника),
  `components/LineDe.vue` (немецкая строка по словам), `PerformancePlayer.vue`, `SongView.vue`.

Служебное поле `anchored` (число слов с якорем Whisper) пишет конвейер для консенсуса записей; плеер его не читает.

Отбор вариантов ПЕРЕПИСАН (2026-09-10, по итогам ревизии всех 289 опубликованных): вариант публикуется, только если спетое слово
существует (немецкий словарь hunspell de_DE или словарь корпуса), в строке этой записи подменено не больше одного слова (две и
более подмены — след ошибки выравнивания, не исполнение), и спетое не совпадает со словом текста в старой орфографии или как омофон
(Brod/Brot, itzt/jetzt, viel/fiel, sah's/saß). Ревизия сняла 274 из 289; осталось 15 правдоподобных (erfroren у Квастхофа в D 911/4,
Rosse вместо Hengste в D 166, Brust вместо Busen в D 716, schreite и schauen в D 93/1 и др.). Было: фильтр `variants_filter.py`
пропускал «сильный вариант либо подтверждённый второй записью» без словарной проверки.

Служебное поле `variant_candidates` — слова, услышанные распознавателем иначе, но не прошедшие фильтр вариантов
(`variants_filter.py`: сильный вариант, либо подтверждённый второй записью или пользователем); плеер их не показывает,
они идут в очередь на прослушивание. Подтверждённые пользователем варианты — `planning/audio/variants-confirmed.json`.

## Поле `holes` в файле таймингов (2026-09-09)

Запись, выложенная лучшей из имеющихся версий, но не прошедшая ворота (см. `audio-alignment.md`, «порог публикации переписан второй
раз»), несёт служебное поле `"holes": [{"a", "b", "sec", "why"}]` — границы дыры в секундах, длительность и причина
(«растянутое слово», «до первого слова», «между словами»). Приложение поле не читает (загрузчик проверяет только `d`, `videoId`,
`route`); оно для очередей прослушивания и последующей пересборки. У записей, прошедших ворота, поля нет.

## Загрузка файлов таймингов — лениво (2026-09-09)

Файлов 2400+ (22 МБ). Жадный `import.meta.glob(..., { eager: true })` вкладывал их все в бандл: 17 МБ на каждого посетителя, локальная
сборка падала по памяти. Теперь `utils/timings.js` строит индекс по именам файлов (`d<prefix>-<videoId>.json`, videoId — 11 знаков)
и подгружает файл только для выбранной записи (`getTiming` возвращает Promise, `SongView` ждёт его в `watch`). Поле `fragment` в
`performances.json` и пометка «фрагмент» в плеере — см. `youtube-performances.md`.

## Файлы песен — тоже лениво (2026-09-10)

Песни (618 файлов, 23 МБ) больше не входят в бандл: `SongView.vue` держит `import.meta.glob('../data/songs/*.json')` без `eager`
и грузит файл выбранной песни по требованию (`song` — ref, заполняемый в `watch` по `songFile`; пока грузится новая, на экране
прежняя). Поиск по тексту берёт строки из отдельного модуля `virtual:search-text`, который собирает плагин в `app/vite.config.js`
из файлов песен на сборке (не отстаёт от текстов, в репозитории не лежит) и который `utils/searchIndex.js` подгружает при первом
поиске по тексту; до его прихода поиск отвечает `pending`, вызывающие показывают «Ищу в тексте песен…» и повторяют запрос по
`textIndexReady`. Меню печати перед печатью предзагружает выбранные песни. Итог: основной бандл ≈ 0,5 МБ вместо 17 МБ, первое
открытие на телефоне — секунды вместо ~20 с. Основание: замер 2026-09-09 (4G, 4× медленный процессор: 20 с до текста).

## Показ вариантов исполнения ПЕРЕПИСАН (указание пользователя 2026-09-09, 13:05)

Дословно: «должно показываться не так. Должно быть как изначально в песне Erstarrung: вариант исполнения идёт отдельным этажом, и этот
этаж подсвечивается, если в данный момент исполняется»; «справа в русском переводе неверно — справа тоже должно правильно работать».
Было: спетое слово из `variants` файла таймингов подставлялось в немецкую строку вместо слова текста (пунктирное подчёркивание), а
правая колонка подсвечивала сегмент слова текста.
Стало:
- **Немецкая строка** (`LineDe`): спетое слово стоит **отдельным этажом над словом текста** — так же, как редакторский вариант
  `variant_de` в данных песни; если спетое совпадает с редакторским вариантом, этаж один. Когда слово исполняется, подсвечивается
  этаж (спетое), а не слово текста; когда певец поёт как в тексте — подсвечивается слово текста, этаж (если есть) нет.
- **Правая колонка** (`InterlinearLine`): если спетое слово — редакторский вариант, подсвечивается его этаж `variant_ru`; если спетое —
  другое слово той же строки (перестановка), подсвечивается сегмент этого слова; иначе — сегмент слова текста.
- Механика в `SongView.sungSegInfo`, `LineDe.tierOf`; строке с этажом даётся место сверху (`with-variant` / `has-tier`).
