# План масштабирования перевода на весь корпус (~600 песен)

Задача: качество не ниже принятого пилота («Гретхен», редакция 2026-08-17) на всём корпусе, внутри лимитов подписки, быстро. Статус: **план; массовый перевод не начат** (по правилам — ждёт явного утверждения пользователя).

## 1. Анатомия стоимости пилота

«Гретхен» стоила порядка нескольких миллионов токенов субагентов, но большая часть — **разовые вложения**, которые не повторяются: создание правил (style.md, протоколы, каталог ИИ-артефактов), фонд певцов, методика словарной дорожки, четыре круга переработки с выработкой планки. Маржинальная стоимость песни при отлаженном конвейере — на порядок ниже.

## 2. Пять рычагов экономии (в порядке важности)

### 2.1. Словарный кэш проекта (главный рычаг)
Замер по корпусу (618 текстов): 100 079 словоупотреблений, **12 950 уникальных словоформ**, 80% корпуса покрывают 1932 формы, форм-одиночек 6500, средняя форма повторяется 7,7 раза. Лемматизация сожмёт ещё (~7–8 тыс. лемм).
- `planning/dictionary/` — по записи на лемму: значение эпохи (цитаты Adelung/Grimm), современный контроль (DWDS/Duden), RU-кандидаты (БНРС и др.), рекомендация, регистр, оговорки. Формат — как в gretchen-dictionary.md.
- Слово исследуется **один раз на корпус**; повторное вхождение — чтение кэша (≈0 токенов). Контекстные отступления от кэша — только с пометкой в словарной записи (запись накапливает контексты).
- Скрипт-подготовка песни (0 токенов): словоформы текста → сверка с кэшем → список непокрытых слов для дорожки. Первые песни наполняют кэш (дорого), к середине корпуса покрытие станет почти полным.

### 2.2. Амортизируемые досье
- **Поэтные досье** (`planning/research/poets/`): биография, стиль, verified-факты, отношения с Шубертом — один раз на поэта; Гёте амортизируется на ~70 песен, Шиллер ~40, Мюллер 44, Майрхофер ~47.
- **Реестр сквозных источников**: буклеты Hyperion по томам (одна выгрузка тома покрывает ~15 песен), документы Дойча (уже освоены), NSA-данные каталога (уже собраны), Kammermusikführer и пр. Источник читается один раз, факты наследуются песнями.
- **Дистиллят правил перевода** — компактный рабочий промпт вместо 67-КБ свода (заготовка уже в репозитории); плюс дистиллят style.md.

### 2.3. Дифференциация объёма при единой планке языка
Планка «не ниже Гретхен» = **точность перевода, верность фактов, живой русский** — одинаково для всех. Но объём «О песне» пропорционален литературе о песне: у знаменитых (~100) есть материал на 15–20 подразделов, у редких (~450) — честные 4–7 (дата/контекст из каталога, поэт из досье, заметка Hyperion, словарные наблюдения). Это не экономия на качестве, а отражение реальности источников. **Требует подтверждения пользователя.**

### 2.4. Модельная лестница и скрипты
- Механика — скриптами (0 токенов): подготовка слов, все структурные проверки (покрытие DE-слов сегментами, ё/типографика/кавычки, диапазоны аннотаций, валидность JSON), сборка страниц, дежурные грепы по стилевым маркерам.
- Дешёвая модель + low effort: выгрузка цитат по известным URL-шаблонам словарей, извлечение из буклетов, механическая сверка.
- Основная модель: сам перевод, аннотации, тексты «О песне», арбитраж спорных слов, приёмка (язык+факты).

### 2.5. Волны и конвейер
- Волны по 8–15 песен; внутри волны — pipeline() без лишних барьеров: подготовка → словарная дорожка непокрытых слов → перевод+аннотации → «О песне» (из фактов) → двухагентная приёмка (редактор-язык + факт-гейт) → правки → сверка дельты → публикация.
- 2–4 воркфлоу параллельно (правило дисковой фиксации: результат каждой песни коммитится сразу).
- После волны: коммит, отчёт (токены на песню, время, попадание в кэш), калибровка следующей волны.

## 3. Контроль качества при масштабе (без ретро-кругов на каждую песню)
Гретхен потребовала многих кругов, потому что планка вырабатывалась. Теперь она записана в правилах, и конвейер строится так, чтобы писать сразу правильно:
- жёсткий набор правил в промптах (дистилляты) + словарный кэш (уже проверенные решения);
- обязательная двухагентная приёмка каждой песни + цикл «правка → сверка» до чистого прохода (протоколы 3б/3в);
- моя вычитка вслух 1–2 песен из каждой волны целиком; выборочное чтение пользователем — лучший калибратор планки;
- метрика волны: число находок приёмки на песню должно падать; рост — стоп и разбор.

## 4. Лимитная дисциплина
- Остатки лимитов изнутри не видны — правда у пользователя в `/usage`; внутри меряем токены субагентов на песню и на волну.
- **Пилотная волна-замер** (5–8 песен разных типов: знаменитая, средняя, редкая, куплетная) даст фактическую цену песни; после неё — прогноз на корпус и недельный темп, согласованный с наблюдаемыми лимитами.
- Ожидание (проверить замером): редкая песня ~60–120 тыс. субтокенов, знаменитая ~250–400 тыс.; корпус целиком — порядка 100 млн субтокенов, что при недельном дозировании волнами реалистично; точность даст только замер.
- Тяжёлые волны не начинать в конце 5-часового окна; скриптовую работу (сборка кэша-скелета, подготовка) — в любое время, она почти бесплатна.

## 5. Порядок запуска (после утверждения пользователем)
1. Построить скелет словарного кэша скриптом (частотный список, лемматизация, заготовки записей) — почти бесплатно.
2. Наполнить кэш топ-500 форм (одна волна словарных агентов — самая выгодная инвестиция корпуса).
3. Досье трёх главных поэтов первой волны.
4. Пилотная волна перевода 5–8 песен → замер → отчёт пользователю → калибровка → серийные волны.
