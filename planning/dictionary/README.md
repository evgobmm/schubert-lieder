# Словарный кэш проекта

Слово исследуется **один раз на весь корпус** (по протоколу словарной дорожки: Adelung/Grimm → DWDS/Duden → БНРС/Multitran/PONS, с дословными цитатами), результат сохраняется здесь и переиспользуется всеми песнями. Главный рычаг экономии конвейера перевода (`planning/translation-scale-plan.md`).

## Состав

- `forms-index.json` — частотный индекс всех словоформ корпуса (12 791 форма; топ-500 покрывают 63,5% словоупотреблений, топ-2000 — 80,6%). Генерация: скрипт в истории коммитов / пересборка по `app/src/data/songs/*.json`.
- `entries/<лемма>.json` — исследованные записи: `{lemma, era, register, ru_candidates, recommendation, caveats, evidence, source, song, status}`. Засеяно 34 записями из исследования «Гретхен» (`planning/research/gretchen-dictionary.md`).

## Использование в конвейере

1. Подготовка песни (скрипт, 0 токенов): словоформы текста → сверка с `entries/` → список непокрытых знаменательных слов.
2. Непокрытые слова — словарной дорожкой (агенты), результат **сразу добавляется в entries/** (коммитом), даже если песня ещё в работе.
3. Переводчик получает в промпт готовые записи покрытых слов; отступление от рекомендации в контексте — допустимо с сигнализацией, запись пополняется контекстом.
4. Служебные слова (артикли, местоимения, союзы из топа индекса) записей не требуют — их ведёт свод правил перевода.

## Договорённости

- Ключ — лемма (нижний регистр); формы одной леммы (finde/findet/fand) — одна запись, формы перечисляются внутри при необходимости.
- `status`: `verified` (дорожка пройдена с цитатами) / `draft` (черновик, в тексты не попадает).
- Записи не переписываются молча: дополнение контекстов — append, пересмотр рекомендации — с пометкой и причиной.
