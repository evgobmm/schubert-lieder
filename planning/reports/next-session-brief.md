# Бриф для новой сессии: волна v2 (после приёмки пользователем)

Контекст: `planning/reports/translation-run-state.md` (последние записи — v2-калибровка, замер, меры экономии), правила `docs/rules/*.md`, закон агентов `planning/catalog/one-shot-brief.md`. Главный цикл — Opus (`.claude/settings.json`), Fable — только агент финальной редактуры.
Состояние: v2-конвейер откалиброван и обкатан волной №2 (12 песен, 2,7M токенов ≈ $8 на песню с оркестратором); переведённых страниц 60. Волна — только после приёмки пользователем опубликованных страниц и по его «поехали».
Дисциплина главного цикла — не больше ~6 ходов на партию, ничего большого не читать:
1. `bash planning/scripts/wave-prep.sh <W> <d>...` (пакеты, предзагрузка, бандлы, args; ~1 мин/песня сети) — один ход.
2. `Workflow({scriptPath: 'planning/catalog/wave-v2-workflow.js', args: <содержимое W/args.json>})` — ВСЯ волна (40–50 песен) одним запуском; скрипт гонит 6 цепочек одновременно (`args.parallel` переопределяет), sonnet/sonnet/opus/fable/opus, один ремонт при нечистой сверке. Ожидание ≈ 4–5 ч на 45 песен; ждать уведомления, не поллить.
3. `node planning/scripts/wave-report.js <runId> <W>` — итоги; чистые → `node planning/scripts/publish-candidates.js <W> <d>...`, коммит+пуш; нечистые — ремонт по списку (конвенция сегментов — CONV в скрипте) и повторная сверка.
4. `node planning/scripts/usage-delta.js <ISO-старта>` + строка в журнал. Дельту ccusage просить у пользователя после волны.
Состав волны №3 по умолчанию (≈45): Хёльти 13 + Козегартен 13 (кроме D 319 на 152 строки) + Клаудиус (все не переведённые) + короткие Майрхофера до 45; список — `node planning/scripts/wave-args.js`; без досье (Шиллер, Маттисон …) — сначала досье поэта (один sonnet-агент).
Неприкосновенно: 24 песни Winterreise. Мониторов с событиями не ставить.
