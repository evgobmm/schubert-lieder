# Кампания возврата снятого — итоговый отчёт

**Когда:** 4 сентября 2026 года, один заход (десять подволн).
**Что это было:** сплошной пересмотр всего, что финальный редактор (Fable) когда-либо снимал со страниц с пометкой «нет опоры». Часть таких утверждений была верной — опору тогда просто не нашли, чаще всего потому, что в бандл попадала усечённая словарная карточка или неполный файл фактов.

## Цифры

| | |
|---|---|
| снятого в журналах воркфлоу всего | 2007 пунктов |
| из них класс «без опоры» (на пересмотр) | 1622 пункта в 301 песне |
| песен разобрано | 301 из 301 — очередь исчерпана |
| пред-триаж по карточкам (без агентов, 0 токенов) | 127 пунктов в 74 песнях |
| подтверждено и заявлено к возврату | 507 пунктов в 172 песнях |
| отклонено (снято правильно) | 1022 пункта |
| новых фактов вписано в файлы фактов | 214 |
| страниц изменено и опубликовано | 152 |
| файлов фактов изменено | 178 (+1897 строк) |

Расход по локальным транскриптам за окно кампании (13:09 UTC → конец; в окно входят и досье поэтов, шедшие параллельно): **434,3 млн биллинговых токенов** — Sonnet 245,0 млн (триаж и проверка источниками), Opus 130,0 млн (возврат формулировок + главный цикл), Fable 59,3 млн (вычитка).

## Как это делалось

Конвейер на песню (`planning/catalog/restore-claims-workflow.js`), три этапа:

1. **Триаж и проверка** (sonnet) — разбирает список снятого по четырём исходам: «ошибка» (снято правильно), «опора уже есть» (полная карточка, досье поэта, файл фактов), «нашлась опора» (проверка по источникам, новый факт с цитатой и URL), «не подтвердилось» (строка в раздел «Не подтвердилось» файла фактов). Результат — `claims.json`.
2. **Возврат** (opus) — пишет файл правок, прогоняет `apply-edits.js`; страница собирается заново из снимка, валидатор и линт стиля обязательны.
3. **Вычитка** (fable) — смотрит только возвращённое: опора, дубли с соседними сносками и разделами, диапазоны сносок, язык.

Подволны по 30–35 песен, между ними — публикация через `publish-candidates.js` (гейт «сначала факт»), коммит и пуш. Постановка страниц в рабочий каталог — `stage-published.js`, чтобы правки всегда ложились на опубликованную версию.

## Что кампания попутно выявила

- **Главная причина ложных снятий подтвердилась**: словарные карточки приходили к редактору усечёнными, и он снимал верные толкования как «не подтверждённые базой». 127 таких пунктов вернулись вообще без участия агентов — по полным карточкам из кэша.
- **Факты, сформулированные шире источника.** D 745: Ф23 утверждал, что при жизни Шуберта вышли только две песни цикла Шлегеля «Abendröte», опираясь на карточки шести песен из одиннадцати; абзац сужен до фактического перечня. Такие факты стоит перепроверить точечно — формулировка факта может быть шире своей цитаты.
- **Возврат может быть неверным.** D 256: заявленная опора (карточка *froh*) не содержала утверждения о «крылатом слове» Гёте; вычитка возврат отменила и записала причину. D 634: возвращённое толкование *schwellen* «о прибывающей воде» карточкой не подтверждается — переписано по карточке.
- **Три сонета Петрарки — D 628, 629, 630** — числятся в индексе как «только текст» (`ready: false`), хотя в рабочем каталоге волны лежат готовые страницы на 26–30 КБ. Опубликовать их нельзя: файлов фактов в репозитории нет (только `-top5.md`), гейт не пропускает. Возвраты, применённые к D 628, осели в кандидате. **Требуется отдельная работа**: прогнать этап фактов для трёх песен и опубликовать.
- **Расхождение копий фактов.** Файлы фактов в каталогах волн отстают от репозиторных (агенты дописывают факты в репозиторий). Гейт публикации это ловит («файл фактов волны беднее репозиторного — НЕ копирую»), но при сборке новых бандлов копии надо освежать.
- **D 240** (`Huldigung`): вычитка D 719 заметила, что слово *süß* сняли там по той же ложной причине; страница в кампанию попала, но проверить её отдельно не помешает.

## Инциденты и что из них следует

- **Затирание возвратов пустым файлом правок.** Этап вычитки, не найдя что править, переписывал файл правок пустым списком и заново прогонял `apply-edits.js` — страница откатывалась к снимку до возврата. Потеряно было 12 песен (D 44, 221, 281, 282, 369, 403, 526, 542, 553, 672, 715, 807), обнаружено сравнением кандидата со снимком, песни прогнаны заново. Промпт вычитки исправлен: **дописывать в существующий файл правок и не запускать apply-edits, когда править нечего**. С тех пор перед каждой публикацией сверяю кандидата с опубликованной версией — если они совпадают, возврат не дошёл.
- **Откат файлов фактов при публикации.** Публикатор копировал файл фактов из волны поверх репозиторного, а тот был свежее. Добавлена защита: файл копируется только если фактов в нём не меньше.
- **Слаги руками.** Дважды выдумал слаг не по индексу, агенты отказались трогать чужие файлы. Слаги берутся только из `app/src/data/index.json`.
